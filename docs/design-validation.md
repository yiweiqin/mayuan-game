# 本轮规则核验与范围

【本轮确认】规则已经改为历史参考事件库、背景概率、具体制度事件，以及长期未解决问题引发危机。旧版固定制度二选一、手动召回讨论和“全部选择均可通关”的推演结论不再适用。

本页记录设计层面的局部核验，不表示完整游戏、完整事件库或全部随机历史路径已经实现。

## 一、需要检验的因果链

- 同样的时代，前面的选择不同，候选事件及概率能够不同。
- 没有土地归属问题，不应出现无原因的土地争议；没有组织活动与变革诉求，不应凭空出现革命；没有对外争端和交涉失败或冲突升级，不应凭空出现战争。
- 沿用旧制后保留具体问题，持续时间实际增加；问题到期后出现符合前因的公开争议和严重危机。
- 部分让步、换时代和换事件标题不能清零原问题；真正解决才关闭相应记录。
- 危机可以减少生产力，恢复生产不能超过本次损失；保留已经掌握的技术和进入的时代，以便继续恢复。

## 二、数值可达性的边界

在没有严重危机打断时，普通活动可以持续积累至日常上限，关键发展再衔接20、50、90、140、180。等待保障避免一直抽不到发展机会；时代界限从规则文档读取。

危机可能额外损失4或8点，不受普通小损失限制。因此旧版“每三个普通事件至少净增长一点”的结论只能描述普通生产片段，不能据此声称战争或革命之后每局都必然进步。

玩家最终通过具体事件处理问题并恢复生产时，应有继续发展的路径；若持续选择扩大冲突或拒绝可行处理，可能反复倒退。这个后果保留在设计中，不用万能制度入口消除。

## 三、复现检查

运行[规则核验脚本](../tools/validate_design.py)：

```
python tools/validate_design.py
```

脚本包含背景概率示例、危机条件、问题持续时间与恢复计算的情境检查，并推演无严重危机的发展路径和危机损失后的恢复路径。它不实现完整的事件调度、所有群体关系、全部随机后果与存档系统。

2026年10月9日本轮运行结果：

| 检查 | 结果 |
| --- | --- |
| 背景概率、危机前因、问题持续和恢复边界 | 21项情境检查通过 |
| 无严重危机、相关问题已得到处理的发展路径 | 32条参考路径均可达到180，只说明这些路径存在 |
| 不同阶段遭遇4点或8点损失后的恢复 | 20条路径均可恢复至本时代日常上限，随后接上发展主题 |
| 中文图表与文档链接 | 15张图的可见文字无英文，所检本地链接均存在 |
| 图表语法 | 15张图均通过图表解析器检查 |

恢复推演包含生产力跌到已进入时代的起始界限以下的情况。它保留时代和技术，未假设恢复两次就能补回全部损失；例如从96损失8后，两次恢复只回到92。

## 四、还需要后续验证什么

- 根据教材、史料与研究整理足够丰富的事件库，区分史实与游戏假设分支。
- 检查模板多寡是否意外稀释某类事件概率，以及连续事件是否符合因果。
- 用完整调度器验证多个问题同时到期、发展机会与危机优先级、恢复阶段暂停、暂缓次数和重复提交。
- 在真正的游戏中测试保存、读档、固定抽取结果、旧分支不能领奖等要求。
- 课堂试用三个和六个回合的节奏、危机损失、恢复速度及每个选项的解释。

上述持续回合、机会份数和损失数值是【新增设计】的试用参数，不是用户已确认的历史规律，也不是现实战争或革命的定量模型。
